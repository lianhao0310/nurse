## 1. 背景与目标

### 1.1 痛点
- **听不懂**：老年患者面对医生口头医嘱，常因方言、语速、专业术语而听不懂、记不全。
- **记不住**：一次就诊可能涉及 4~6 种药物、多种剂量频次与复诊安排，纸质小条易遗失。
- **做不对**：用药时间（空腹/饭后）、饮食禁忌（高血压忌腌制、糖尿病忌高糖）执行偏差大。
- **没人管**：独居老人、慢病患者缺乏持续照护，子女远程无法掌握执行情况。
- **不会急**：出现低血压、低血糖等异常时，不知道何时该就医。

### 1.2 产品定位
一句话：**把一次医患对话，自动变成患者（及子女）看得懂、能执行的私人护理计划。**

私人护士是一款面向**慢病患者与老年人群**的 AI 护理助手 App，以「录入医嘱 → 解析 → 提醒 → 药箱管理 → 档案沉淀」为主链路，将非结构化的问诊对话转化为结构化的护理执行体系。

### 1.3 设计目标
| 维度 | 目标 | 状态 |
|------|------|------|
| 准确率 | 药物/剂量/频次关键信息抽取准确率 ≥ 95%（AI 模型 + 人工可校验） | ✅ |
| 上手成本 | 老人 3 步内完成一次录入（适老化） | ⚠️ 大字体已实现，语音播报未实现 |
| 时效性 | AI 解析 60 秒内生成结果（流式输出实时可见） | ✅ |
| 可干预 | 所有 AI 生成内容支持人工编辑、纠错、确认 | ✅ |
| 可信赖 | 不替代医生诊断，仅做「执行层」转化与提醒 | ✅ |

## 2. 目标用户与场景

### 2.1 用户画像
| 角色 | 特征 | 核心诉求 | 状态 |
|------|------|----------|------|
| 主用户（患者） | 55+ 慢病患者，高血压/糖尿病/冠心病等多见 | 听得懂、记得住、有人提醒 | ✅ |
| 照护者（子女） | 30~50 岁，异地或同住 | 远程掌握父母用药与健康 | 📋 未实现 |

### 2.2 核心场景
1. ✅ **门诊就诊**：诊室内用 App 录音/粘贴医嘱，离院即可看到生成的用药与检查结果。
2. ⚠️ **复诊随访**：引擎能计算复诊日期并展示，但未生成多级提醒（T-7/T-1/当天）。
3. ✅ **居家执行**：到点用药提醒（早/中/晚）、每日库存扣减、缺药告警。
4. ⚠️ **异常处置**：引擎能生成风险预警知识卡，但无患者主动上报症状→分级预警的交互。
5. 📋 **家属协同**：未实现。

## 4. 核心功能详解

### 4.1 医嘱采集与转写 ✅
- **入口**：问诊记录详情页「🎙 录音」按钮，使用浏览器 Web Speech API（zh-CN，连续模式）实时转写到医嘱文本框。
- **兜底**：支持「📁 上传录音」归档音频文件（不转写）；支持直接粘贴/编辑文本。
- **隐私**：录音和解析全在本地完成，AI 调用时仅发送文本/图片到用户配置的 LLM 接口。
- ⚠️ **未实现**：云端 ASR、医生-患者角色分离、方言热词增强。

### 4.2 医嘱解析引擎 ✅
两条路径，优先 AI，回退本地规则引擎：

**路径 A：AI 智能解析（ai.js）**
- `analyzeConsult`：医嘱文字 + 检查图片 + 处方图片 → `{ advice, examResults[], prescription[] }`
- `analyzeAdvice`：医嘱 + 历次指标趋势 + 当前用药 → `{ diet[], taboo[], text }`
- 支持 OpenAI 兼容接口（智谱 GLM、DeepSeek、通义千问、Moonshot 等）
- 流式输出（SSE），实时展示解析进度
- 文本模型自动跳过图片；带图片失败回退纯文字重试

**路径 B：本地规则引擎（engine.js）**
- 病种知识库（6 种：高血压、2型糖尿病、冠心病、高血脂、慢阻肺、痛风）
- 药物词典（14 种常见药，含别名/同音纠错）
- 正则抽取：剂量、频次、服药时间、监测项、复诊日期、生活任务
- 输出四模块：`{ diseases, medications, tasks, advice, risks, reminders }`

> 引擎只做「执行层转化」，不对疾病下诊断、不推荐新药，输出标注「仅供参考，请遵医嘱」。

### 4.3 用药提醒 ✅
- 数据源：药箱（cabinet）中 `status=active` 的药品，按 `timeSlots`（早/中/晚）自动排程。
- 首页用药看板按时段分组展示，点击打卡（toggle → `dailyDone` 记录，保留 7 天）。
- 系统通知：若开启通知权限，对未打卡药品按 `reminderTimes`（默认 08:00/12:30/19:00）设定时通知。
- 每日库存扣减：`runDailyDecrement` 按「单次用量 × 时段数」自动扣减，扣到 ≤0 标记缺药。
- 缺药告警：首页横幅展示 `status=out` 或 `qty ≤ threshold` 的药品。
- ⚠️ **未实现**：原生后台闹钟（当前依赖页面打开时的 setTimeout）、用药窗口柔性提醒、连续未打卡通知家属。

### 4.4 药箱与药单管理 ✅
- **药箱（cabinet）为药品主档**，按药名唯一：厂家/别名/单位规格/库存/单次用量/时段/餐次/阈值/状态/备注/针对病症。
- **药单（orders）条目只记引用属性**：药名/厂家/别名/规格/数量/总数量/单价。药名创建后不可改。
- **库存同步**：药单保存/删除/条目增删均自动 diff 同步药箱（新药入库、编辑按差额调整、删除回退，无引用药品自动清理）。
- **新药建档**：药单内添加新药可展开全属性一次建档到药箱。
- **每日消耗**：由「单次用量 × 时段数」自动计算，不再手动录入。

### 4.5 检查报告与指标趋势 ✅
- 检查报告实体：标题/日期/属性（自测 self / 医院 hospital）/指标列表（指标名/数值/单位/参考范围/异常标记）。
- **指标单位/参考值自动记忆**：填过相同指标直接填充，修改任一处同名指标同步全部（`indicatorMeta` 隐式维护）。
- **关注指标**：通过标题右侧 ⚙ 管理，趋势图 SVG 折线，支持整页左右滑动切换指标。
- AI 分析可从检查报告图片提取指标并覆盖/新建报告。

### 4.6 问诊记录 ✅
- 关联「医院 + 就诊日期 + 医生 + 医嘱文字 + 录音 + 药单图片 + 检查报告图片」。
- 详情页内嵌与药箱/检查明细同构的药单与报告卡片——点击进编辑、左滑删除（级联回退药箱库存）。
- 医院药单/报告的来源与日期随问诊记录自动同步；自建/自测可自由修改。
- AI 分析结果可编辑后保存，覆盖已关联的药单/检查报告。

### 4.7 私人护士叮嘱（饮食与禁忌）⚠️
- 规则引擎从 DISEASE_KB 按病种生成禁忌/饮食建议。
- AI 医嘱分析（`analyzeAdvice`）结合历次指标趋势和当前用药，生成个性化饮食/禁忌/生活建议。
- 首页 AI 医嘱页签展示历次问诊的饮食/禁忌卡片。
- ⚠️ **未实现**：语音朗读、卡片化「可做/忌做/推荐食材」分类展示。

### 4.8 风险预警与异常处置 ⚠️
- 规则引擎从 DISEASE_KB 生成风险预警知识卡（green/yellow/red 三级）。
- ⚠️ **未实现**：患者主动上报症状→分级预警交互、监测值越界自动触发预警、红色预警就医指引+通知家属。

### 4.9 健康档案 ✅
- 落盘到手机文件系统（Capacitor Filesystem 写 Documents/nurse-data.json），非电容环境回退 localStorage。
- 支持导出/导入单个 JSON，换机可完整迁移历史。
- 指标趋势图自动汇总所有报告的同名指标为时间序列。

### 4.10 家属协同 📋
- 未实现。规划：患者授权绑定家属、家属端查看护理计划与执行率、留言提醒、异常通知、代为修改设置。

## 5. 医嘱解析引擎详细设计

### 5.1 本地规则引擎（engine.js）

**病种知识库（DISEASE_KB，6 种）**
| 病种 | 禁忌 | 饮食 | 监测 | 风险 |
|------|------|------|------|------|
| 高血压 | 腌腌制/剧烈起身 | 低盐 | 血压 | 头晕→黄色 |
| 2型糖尿病 | 테高糖 | 控糖定时 | 血糖 | 低血糖→红色 |
| 冠心病 | 테剧烈运动 | 低脂 | 血压/心率 | 胸痛→红色 |
| 高血脂 | 테高脂 | 低脂低胆固醇 | 血脂 | — |
| 慢阻肺 | 테吸烟 | 高蛋白 | 血氧/心率 | 气促→黄色 |
| 痛风 | 테高嘌呤/酒精 | 低嘌呤 | — | 急性发作→红色 |

**药物词典（MEDICATIONS，14 种）**
含苯磺酸氨氯地平片、缬沙坦胶囊、硝苯地平控释片、美托洛尔缓释片、二甲双胍缓释片、阿卡波糖片、格列美脲片、胰岛素注射液、阿托伐他汀钙片、瑞舒伐他汀钙片、阿托伐他汀钙片、阿司匹林肠溶片、非布司他片、通心络胶囊、复方丹参滴丸。每种含别名/同音纠错和关联病种。

**解析管线**
```
医嘱文本 → 病种初判（关键词匹配）
  → 药物抽取（词典+正则，含同音纠错）
  → 剂量/频次/时间抽取（正则+中文数字）
  → 任务抽取（监测/复诊/生活）
  → 病种知识库匹配（禁忌/饮食/风险）
  → 提醒时间表生成
  → 输出四模块 JSON
```

### 5.2 AI 智能解析（ai.js）

**三种 Prompt 模式**

| 模式 | 函数 | System Prompt | 输入 | 输出 |
|------|------|---------------|------|------|
| 通用解析 | `parse` | SYSTEM_PROMPT | 转写文本+图片 | `{diseases, medications, tasks, advice, risks, summary}` |
| 问诊分析 | `analyzeConsult` | CONSULT_SYSTEM | 医嘱+检查图片+处方图片 | `{advice, examResults[], prescription[]}` |
| 医嘱分析 | `analyzeAdvice` | ADVICE_SYSTEM | 医嘱+趋势+用药 | `{diet[], taboo[], text}` |

**模型兼容**
- 纯文本模型（自动跳过图片）：glm-4.7-flash、glm-4-flash、deepseek-chat、qwen-turbo、moonshot-v1-* 等
- 视觉模型（支持图片）：含 vision/vl/gpt-4o/claude-3/gemini 等标识
- 请求：OpenAI 兼容 `/chat/completions`，`temperature=0.2`，`response_format=json_object`，SSE 流式

**错误处理**
- 401/404 专属提示；网络/CORS 错误提示
- 带图片失败自动回退纯文字重试
- AI 未配置或失败时回退本地规则引擎

### 5.3 质量与可信
- ✅ **必带免责声明**：「本结果由 AI 生成，仅供参考，请遵医嘱」
- ✅ **人工校验闭环**：AI 结果在弹窗中可逐条编辑后保存
- 📋 **用药冲突检测**：未实现（重复成分弹窗提示）

## 6. 系统总体架构

### 6.1 架构概览（实际实现：纯端侧本地闭环）

```
┌─────────────── 移动端（Capacitor iOS / Android）──────────────────┐
│  WKWebView 运行 frontend/（纯静态，零构建）                          │
│                                                                   │
│   index.html    页面骨架（4 Tab + 2 视图 + 8 弹窗）                 │
│   styles.css    样式（iOS 风格，适老化大字体）                       │
│   storage.js    持久化：Filesystem JSON / localStorage             │
│   engine.js     本地规则解析引擎（离线，零后端）                     │
│   ai.js         OpenAI 兼容模型调用（GLM 等，流式）                  │
│   app.js        交互 / 渲染 / 路由 / 提醒 / 档案（2194 行）          │
│                                                                   │
│   数据：Documents/nurse-data.json（单文件，明文）                    │
└───────────────────────────────────────────────────────────────────┘
        ↑ 同一套 frontend/ 也由后端静态托管（Web 演示）
┌─────────────── Web 演示后端（可选，FastAPI）──────────────────────┐
│  GET /           → index.html                                     │
│  GET /api/health → 健康检查                                       │
│  POST /api/parse → LLM 解析（失败回退规则引擎）                     │
└───────────────────────────────────────────────────────────────────┘
```

### 6.2 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 移动端技术 | 纯 Web（原生 JS）+ Capacitor | 零构建、同一套代码 Web/原生双跑 |
| 本地存储 | 单 JSON 文件 | 简单、可导出迁移、无需数据库 |
| 解析引擎 | 前端本地 engine.js + 前端直连 LLM | 离线可用、隐私优先、零后端依赖 |
| 数据模型 | 药箱(cabinet)为药品主档 + 药单(orders)引用 | 主属性与引用分离，库存自动同步 |
| 提醒调度 | 浏览器 setTimeout + Notification API | Web 限制，无原生后台闹钟 |

### 6.3 数据流转（以一次问诊 AI 分析为例）
```
用户录入医嘱/图片
  → saveRecordEdit（静默保存获得 record id）
  → runAIAnalyze
    → NurseAI.analyzeConsult({ adviceText, examImages, rxImages })
    → SSE 流式输出到进度面板
  → openAIModal（可编辑表格展示结果）
  → saveAIModal
    → 保存医嘱到 record
    → 检查结果 → 覆盖/新建 report 并关联
    → 处方药 → 覆盖/新建 order 并关联（库存 diff 同步）
  → showRecordView（刷新详情页）
  → renderRecords / renderCabinet / renderHome（刷新各页）
```

## 7. 数据模型设计（实际实现）

### 7.1 顶层结构（nurse-data.json，VERSION=3）
```json
{
  "version": 3,
  "updatedAt": "ISO时间",
  "lastDecrement": "YYYY-MM-DD",
  "settings": { ... },
  "records": [ ... ],
  "orders": [ ... ],
  "cabinet": [ ... ],
  "reports": [ ... ],
  "indicatorMeta": { ... },
  "followedIndicators": [ ... ]
}
```

### 7.2 实体关系
```
Record(问诊记录) 1──0..1 Order(药单)     via record.orderId
Record(问诊记录) 1──0..1 Report(检查报告)  via record.reportId
Order 1──* Medicine(药单条目)             via order.medicines[]
Medicine ──(by name)── CabinetDrug(药箱主档)
Report 1──* Indicator(指标)               via report.indicators[]
IndicatorMeta(指标记忆) ──(by name)── Indicator
FollowedIndicators(关注指标) ⊂ Indicator names
```

## 8. 提醒调度与推送

### 8.1 提醒生成规则（✅ 已实现）
- 用药提醒：由药箱药品的 `timeSlots`（早/中/晚）+ `reminderTimes`（默认 08:00/12:30/19:00）展开。
- 每日库存扣减：`runDailyDecrement` 对 active 药品按「单次用量 × 时段数」扣减。
- 缺药告警：`status=out` 或 `qty ≤ threshold` 在首页横幅展示。

### 8.2 调度策略
- ✅ 浏览器 `setTimeout` + Notification API（页面打开时有效）。
- ⚠️ 无原生后台闹钟（Web 限制）。
- 📋 规划：原生闹钟（Capacitor 插件）、用药窗口柔性提醒、复诊 T-7/T-1/当天三级提醒。

### 8.3 交互
- 首页用药看板按时段分组，大按钮打卡。
- ✅ 通知点击直达 App。
- 📋 规划：语音播报药名与剂量。

## 9. 隐私、安全与合规

- ✅ **本地优先**：解析和存储全在手机本地完成，AI 调用时仅发送文本/图片到用户配置的 LLM 接口。
- ✅ **数据可控**：用户可随时导出/导入/删除全部数据。
- ✅ **免责声明**：全程标注 AI 辅助、非诊疗建议。
- ⚠️ **存储明文**：nurse-data.json 未加密。
- 📋 **规划**：端侧 AES 加密、字段级脱敏、敏感信息单独同意、不用于训练公开模型。

| Web 演示 | FastAPI（可选） | 仅演示，移动端不依赖 |
| CI/CD | GitHub Actions（macOS runner） | 自动出 .ipa |
| 推送 | Notification API + setTimeout | Web 限制，无原生后台推送 |
