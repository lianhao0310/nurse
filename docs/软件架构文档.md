## 1. 系统概览

**私人护士**是一款面向慢病患者的 AI 护理助手 App。核心闭环：录入医嘱 → AI/规则解析 → 用药提醒 → 药箱管理 → 档案沉淀。

**技术形态**：纯 Web 前端（原生 JS，零框架、零构建）+ Capacitor 封装为 iOS 原生 App。同一套 `frontend/` 代码既在浏览器中运行，也在 WKWebView 中运行。数据全部存储在手机本地，AI 解析由前端直连 LLM 接口完成，**零后端依赖**（后端仅作 Web 演示）。

## 4. 模块职责

### 4.1 前端模块依赖关系

```
index.html
  ├── storage.js   （加载最先，提供 NurseStorage 全局对象）
  ├── engine.js    （提供 NurseEngine 全局对象）
  ├── ai.js        （提供 NurseAI 全局对象）
  └── app.js       （加载最后，入口 boot() → init()）
```

### 4.2 各模块职责

#### storage.js — 持久化与数据层
**全局对象**：`NurseStorage`

**核心职责**：
- 数据归一化：每个实体有 `_norm*` 函数，确保字段完整、类型正确
- CRUD 操作：records / orders / cabinet / reports / settings / done / followedIndicators
- 库存同步：`_syncCabinetDiff`（药单保存前后 diff，按条目 id 对齐，qty 差额累加到 cabinet）
- 数据迁移：`_migrateCabinet`（旧版药品属性从药单迁移到药箱主档）
- 导入导出：`exportJSON` / `importJSON`
- 存储适配：Capacitor Filesystem 优先，回退 localStorage

**关键函数**：
| 函数 | 职责 |
|------|------|
| `load()` / `save(data)` | 读写完整 JSON |
| `_normRecord` / `_normOrder` / `_normMedicine` / `_normCabinetDrug` / `_normReport` / `_normIndicator` | 实体归一化 |
| `_syncCabinetDiff(data, oldMeds, newMeds, fullMap, excludeOrder)` | 药单保存时库存 diff 同步 |
| `_adjustCabinet(data, med, delta, full)` | 调整药箱库存（delta 为差额） |
| `upsertOrder` / `updateOrder` / `deleteOrder` | 药单 CRUD（内部触发库存同步） |
| `setDone` / `getDone` | 用药打卡记录 |
| `setLastDecrement` | 每日扣减日期记录 |

#### engine.js — 本地规则解析引擎
**全局对象**：`NurseEngine`

**核心职责**：离线环境下从医嘱文本抽取结构化信息，无需网络。

**关键函数**：
| 函数 | 职责 |
|------|------|
| `parse_transcript(text)` | 主入口，输出四模块 |
| `detect_diseases(text)` | 病种初判（关键词匹配） |
| `extract_medications(text, diseases)` | 药物抽取（词典+正则+同音纠错） |
| `extract_tasks(text, diseases)` | 任务抽取（监测/复诊/生活） |
| `schedule_reminders(meds)` | 提醒时间表生成 |

**内置数据**：
- `DISEASE_KB`：6 种病种知识库（禁忌/饮食/监测/风险）
- `MEDICATIONS`：14 种药物词典（别名/同音纠错/关联病种）
- `ALIAS_TO_STD`：别名→通用名映射

#### ai.js — AI 智能解析
**全局对象**：`NurseAI`

**核心职责**：前端直连 OpenAI 兼容 LLM 接口，流式输出结构化结果。

**关键函数**：
| 函数 | 职责 |
|------|------|
| `parse(opts)` | 通用解析（transcript+images → 四模块） |
| `analyzeConsult(opts)` | 问诊分析（医嘱+检查图片+处方图片 → advice/examResults/prescription） |
| `analyzeAdvice(opts)` | 医嘱分析（医嘱+趋势+用药 → diet/taboo/text） |
| `isConfigured(settings)` | 判断是否已配置 AI |
| `_chatStream(system, parts, settings, onChunk)` | SSE 流式请求 |

**模型兼容**：
- `TEXT_ONLY_MODELS`：纯文本模型列表（自动跳过图片）
- `VISION_HINT`：视觉模型正则识别（gpt-4o/claude-3/gemini/vl 等）

#### app.js — 应用主逻辑
**入口**：`boot()` → `init()` → 渲染各页 + 绑定事件

**核心模块**（按功能域）：

| 功能域 | 关键函数 | 说明 |
|--------|----------|------|
| 首页看板 | `renderHome`, `renderMedBlocks`, `renderHomeAlerts`, `toggleMed`, `scheduleNotifications` | 用药看板+告警+打卡+通知 |
| 问诊记录 | `renderRecords`, `showRecordView`, `renderRecordEdit`, `saveRecordEdit`, `startRecMic` | 列表+详情编辑+录音转写 |
| AI 分析 | `runAIAnalyze`, `openAIModal`, `saveAIModal`, `runAdviceAnalyze`, `openAdviceModal`, `saveAdviceModal` | 两种 AI 分析模式 |
| 检查结果 | `collectSeries`, `renderExamTrend`, `renderExamList`, `openExamView`, `openFollowModal` | 趋势图+关注指标 |
| 药箱/药单 | `renderCabinet`, `renderOrders`, `openCabinetModal`, `openOrderModal`, `openMedItemModal`, `saveMedItem`, `runDailyDecrement` | 药箱主档+药单+库存扣减 |

## 6. 数据模型

### 6.1 存储格式
单文件 `nurse-data.json`（VERSION=3），Capacitor 环境写入 `Documents/` 目录，否则 localStorage。

### 6.2 顶层结构
```
nurse-data.json
├── version: 3
├── updatedAt: ISO时间
├── lastDecrement: "YYYY-MM-DD"      // 每日扣减日期
├── settings: Settings
├── records: Record[]                // 问诊记录
├── orders: Order[]                  // 药单
├── cabinet: CabinetDrug[]           // 药箱药品主档（按药名唯一）
├── reports: Report[]                // 检查报告
├── indicatorMeta: { 指标名 → { unit, range } }  // 指标记忆
└── followedIndicators: string[]     // 关注指标名列表
```

### 6.3 实体关系
```
Record ──0..1── Order      (record.orderId)
Record ──0..1── Report     (record.reportId)
Order   ──*──  Medicine    (order.medicines[])
Medicine ──(by name)── CabinetDrug
Report  ──*──  Indicator   (report.indicators[])
```

### 6.4 核心实体字段速查

**Record**（问诊记录）：`id, createdAt, visitDate, hospital, doctor, source, transcript, images[], rxImages[], examImages[], advice{text, audio}, orderId, reportId, result, aiAdvice{diet[], taboo[], text, createdAt}, manual, status`

**Order**（药单）：`id, source, date, kind(custom/hospital), recordId, medicines[], images[], aiGenerated`

**Medicine**（药单条目）：`id, name, manufacturer, alias, spec(包装规格), packCount(盒数), qty(总数量), price`

**CabinetDrug**（药箱主档）：`id, name, manufacturer, alias, unit, spec(单位规格), qty(库存), doseAmount, doseUnit, timeSlots[], meal, threshold, status, note, disease`

**Report**（检查报告）：`id, title, date, kind(self/hospital), recordId, indicators[], images[], aiGenerated`

**Indicator**（指标）：`name, value, unit, range, abnormal`

**Settings**：`ai{enabled, baseUrl, apiKey, model}, notifications, largeFont, dailyDone, reminders[], reminderTimes{morning, noon, evening}`

## 7. 核心数据流

### 7.1 问诊记录 + AI 分析流程

```
用户操作                          函数调用                          数据变化
─────────                         ────────                         ────────
点击新增问诊        → openRecord(null) → showRecordView(null)
录入医嘱/图片       → recDraft 暂存
点击保存            → saveRecordEdit
                    → NurseStorage.appendRecord          → records[] 新增
点击 AI 分析        → runAIAnalyze(rec)
                    → NurseAI.analyzeConsult              → SSE 流式输出
                    → openAIModal(可编辑表格)
用户编辑后保存      → saveAIModal
                    → NurseStorage.updateRecord           → record.advice/result 更新
                    → NurseStorage.updateReport/upsertReport → reports[] 覆盖/新建
                    → NurseStorage.updateOrder/upsertOrder   → orders[] 覆盖/新建
                    → _syncCabinetDiff                    → cabinet[] 库存同步
                    → showRecordView(刷新)
```

### 7.2 药单保存 + 库存同步流程

```
用户操作                          函数调用                          数据变化
─────────                         ────────                         ────────
打开药单编辑        → openOrderModal(id)
                    → orderDraft = { medicines: [...] }   → 从 DATA.orders 加载
添加/编辑药品       → openMedItemModal → saveMedItem      → orderDraft.medicines 修改
保存药单            → saveOrder
                    → NurseStorage.upsertOrder
                    → _syncCabinetDiff:
                      - 新药 → _adjustCabinet(建档)       → cabinet[] 新增
                      - 同名药 qty 变化 → diff 调整        → cabinet.qty 更新
                      - 删除条目 → 回退库存               → cabinet.qty 回退
                      - 无引用药品 → 清理                 → cabinet[] 删除
                    → DATA reload
```

### 7.3 每日库存扣减流程

```
App 启动 → init() → runDailyDecrement()
  → 检查 lastDecrement != today
  → 对 cabinet 中 status=active 的药品:
    dayDose = doseAmount × timeSlots.length
    qty -= dayDose
    if qty <= 0 → status = "out"
  → setLastDecrement(today)
  → save(data)
```

### 7.4 首页用药看板渲染

```
renderHome()
  → renderHomeAlerts()           // 缺药/库存不足横幅
  → renderMedBlocks():
    activeMedicines = cabinet.filter(status != disabled/out)
    按 timeSlots 分组（早/中/晚）
    每组展示药品名+剂量+打卡按钮
  → renderPersonalReminders()    // settings.reminders
  → scheduleNotifications()      // 未打卡药品设定时通知
```

## 8. AI 集成详解

### 8.1 三种解析模式

| 模式 | 入口函数 | System Prompt | 输入 | 输出 | 落库位置 |
|------|----------|---------------|------|------|----------|
| 通用解析 | `NurseAI.parse` | SYSTEM_PROMPT | 转写文本+图片 | `{diseases, medications, tasks, advice, risks, summary}` | record.result |
| 问诊分析 | `NurseAI.analyzeConsult` | CONSULT_SYSTEM | 医嘱+检查图片+处方图片 | `{advice, examResults[], prescription[]}` | record.advice/result + report + order |
| 医嘱分析 | `NurseAI.analyzeAdvice` | ADVICE_SYSTEM | 医嘱+趋势+用药 | `{diet[], taboo[], text}` | record.aiAdvice |

### 8.2 请求机制
- OpenAI 兼容 `/chat/completions`，`temperature=0.2`，`response_format=json_object`
- SSE 流式（`stream:true`），通过 `getReader()` 增量解析 `data:` 行，`onChunk` 回调实时输出
- 文本模型自动跳过图片（`TEXT_ONLY_MODELS` 列表匹配）
- 带图片失败自动回退纯文字重试
- 401/404 专属提示；网络/CORS 错误提示
- AI 未配置或失败时回退本地规则引擎 `NurseEngine.parse`

### 8.3 问诊分析结果保存逻辑（saveAIModal）
1. 保存医嘱文字到 `record.advice`，解析结果到 `record.result`
2. 检查结果：已关联报告 → 覆盖指标；未关联 → 新建报告并关联
3. 处方药：已关联药单 → 覆盖药品（同名药继承原条目 id/qty，库存不受影响）；未关联 → 新建药单并关联
4. 刷新 DATA，重新渲染

## 9. 库存同步机制

### 9.1 设计原则
- **药箱（cabinet）为药品主档**：按药名唯一，承载全部主属性
- **药单（orders）条目只记引用属性**：药名/厂家/别名/包装规格/药品数/数量/单价
- **库存自动同步**：药单保存/删除/条目增删均自动 diff 同步药箱

### 9.2 同步算法（_syncCabinetDiff）
```
输入：oldMeds（旧条目）, newMeds（新条目）, fullMap（新药全属性）
1. 按 id 对齐 oldMeds 和 newMeds
2. 对每个 newMed:
   - delta = newMed.qty - oldMed.qty（同 id）
   - 若 delta != 0 或有 fullMap → _adjustCabinet(调整库存)
3. 被删除的条目（oldMap 剩余）:
   - 回退库存（-qty）
   - 若药名无任何药单引用 → 从 cabinet 删除
```

### 9.3 药单条目 id 的作用
- 条目 id 是库存 diff 的对齐依据
- 同名药继承原条目 id → qty 差额为 0 → 库存不受影响
- 新药无 id → 生成新 id → 全量入库

## 14. 关键设计决策与约束

| 决策 | 选择 | 约束/影响 |
|------|------|-----------|
| 零框架 | 原生 JS | 无构建步骤，但大型项目维护成本高 |
| 单 JSON 存储 | nurse-data.json | 简单可迁移，但无索引/事务，大数据量时性能下降 |
| 药箱为主档 | cabinet 按药名唯一 | 药单条目只记引用，库存自动同步，但药名不可改 |
| 前端直连 LLM | ai.js 调 OpenAI API | 零后端，但 API Key 存本机（安全性依赖设备） |
| Web 提醒 | setTimeout + Notification | 仅页面打开时有效，无原生后台闹钟 |
| 图片压缩 | downscaleImage（1280px, 0.82） | 控制 JSON 体积，但大量图片仍可能导致存储膨胀 |

## 15. 已知限制与规划

| 限制 | 影响 | 规划 |
|------|------|------|
| 无原生后台闹钟 | App 关闭后提醒不触发 | Capacitor 本地通知插件 |
| 存储明文 | 数据无加密 | 端侧 AES 加密 |
| 无家属协同 | 单机使用 | 家属绑定/共享后端 |
| 无用药冲突检测 | 重复成分不提示 | 药物成分库 + 冲突检测 |
| 无语音播报 | 适老化不足 | Web Speech Synthesis API |
| 提醒仅按早/中/晚 | 不支持自定义时间点 | 灵活时段配置 |
| 护理任务未独立 | 解析出的任务仅展示不可执行 | 独立任务模块 + 待办执行 |
