# 重点功能与测试说明

> 更新日期：2026-08-23
> 适用范围：`frontend/` + `tests/`
> 目的：明确重点功能清单、测试覆盖与运行方式，供开发与回归参考

---

## 1. 重点功能清单

| # | 功能 | 模块 | 说明 |
|---|------|------|------|
| 1 | 医嘱解析引擎 | `frontend/engine.js` | 本地规则解析，零后端；识别病种 / 提取处方药 / 生成饮食禁忌 / 风险预警 / 用药提醒 |
| 2 | 数据持久化与归一化 | `frontend/storage.js` | 单 JSON 文件（Capacitor Filesystem，回退 localStorage）；归一化 + 旧数据迁移 |
| 3 | 药箱库存同步 | `frontend/storage.js` | 药单保存 / 删除 / 条目增删自动 diff 同步药箱库存；无引用药品自动清理 |
| 4 | 药单 / 检查报告 CRUD | `frontend/storage.js` | `upsertOrder/updateOrder/deleteOrder`、`upsertReport/updateReport/deleteReport` |
| 5 | 问诊记录关联 | `frontend/storage.js` | `appendRecord/updateRecord/deleteRecord`，`orderId/reportId` 关联药单与报告，删除级联清理 |
| 6 | 多图导入 | `frontend/imgupload.js` + `app.js` | 问诊记录 / 药单 / 检查报告导入多张图片，先快照再清空 input 防止 async 遍历中断 |
| 7 | 复制已有药单 / 检查报告 | `frontend/app.js` | 问诊记录页从历史复制内容（药品 / 指标 + 图片）创建新副本并关联，保留旧实体 |

## 2. 测试覆盖

测试位于 `tests/`，使用 Node.js 内置 `node:test`，无外部依赖。

| 测试文件 | 覆盖重点功能 | 用例数 |
|----------|--------------|--------|
| `tests/multi-image.test.js` | 多图导入（#6） | 13 |
| `tests/engine.test.js` | 医嘱解析引擎（#1） | 10 |
| `tests/storage.test.js` | 持久化 / 归一化 / 库存同步 / CRUD / 关联 / 复制副本（#2-#5,#7） | 10 |

### 2.1 多图导入（`multi-image.test.js`）
- `snapshotAndReset`：先 `Array.from` 快照 `input.files` 再重置 `input.value`，防止 async 遍历途中 FileList 被清空只入首张（历史 bug 回归）。
- `collectImages`：遍历快照数组，过滤非图片，跳过压缩失败项，保持顺序。
- 回归用例：bug 模式（直接遍历 FileList 中途清空 → 只处理首张）vs 修复模式（先快照 → 全部保留）。

### 2.2 解析引擎（`engine.test.js`）
- `parse` 返回标准结构（diseases/medications/tasks/advice/risks/reminders/disclaimer）。
- 病种识别：高血压、2 型糖尿病、多病种同识。
- 处方药提取与别名归一（络活喜 → 苯磺酸氨氯地平片，拜糖平 → 阿卡波糖片）。
- 饮食禁忌 / 建议 / 风险预警生成；空文本不报错。

### 2.3 数据层（`storage.test.js`）
- 空数据归一化、药单入库同步药箱、改数量按差额调整、删除回退并清理无引用药品。
- 检查报告指标归一化与空名过滤。
- 问诊记录关联药单 / 报告。
- **复制副本**：创建新药单 / 报告关联到另一记录，解除旧关联但保留旧实体（历史数据不丢）。
- 无 `source` 药单被过滤、删除记录级联清理关联实体。

## 3. 运行测试

```bash
# 全部重点功能测试
npm test
# 或
node --test tests/multi-image.test.js tests/engine.test.js tests/storage.test.js

# 单个文件
node --test tests/engine.test.js
```

> 注：`scripts/boot_test.js`、`scripts/smoke_test.js` 为早期 jsdom 端到端测试，依赖完整 DOM 环境，需在浏览器/jsdom 中运行，不纳入 `npm test`。

---

## 4. 模块可测试性设计

- `engine.js`、`storage.js`、`imgupload.js` 均为 UMD：浏览器挂全局（`NurseEngine` / `NurseStorage` / `NurseImgUpload`），Node 导出 `module.exports`，可直接 `require`。
- `storage.js` 非 native 环境回退 `window.localStorage`，测试中 mock `global.window.localStorage` 即可在 Node 运行。
- 多图导入核心逻辑从 `app.js` 抽出独立模块 `imgupload.js`，避免 IIFE 内部函数不可访问，使快照 / 收集逻辑可独立测试。
